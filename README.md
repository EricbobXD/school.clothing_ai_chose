# 衣序 YIXU

依原有穿搭生成器與設計草圖重新製作的繁體中文 React＋Vite 網站。

## 本機預覽

正式網站：https://ericbobxd.github.io/school.clothing_ai_chose/

推送至 `main` 後，`.github/workflows/deploy-pages.yml` 會執行測試與建置，再發布到 GitHub Pages。部署來源使用 GitHub Actions。Actions 建置時會使用專案子路徑，本機開發保持相對路徑。

需要 Node.js 20.19+ 或 22.12+（建議使用目前的 LTS）。

首次執行 `npm install`，再執行 `npm run dev`，開啟 http://127.0.0.1:4173 。

`npm test` 執行搭配邏輯測試；`npm run build` 輸出正式版本至 `dist/`；`npm run preview` 預覽建置結果。開發版須透過 Vite 啟動。

## 程式結構

- `src/App.jsx`：React 介面、衣櫥狀態、上傳與重置流程。
- `src/recommendations.js`：獨立的搭配建議與配色邏輯。
- `src/styles.css`：響應式視覺樣式。
- `src/main.jsx`：React 進入點。

## 功能

- 可收合的個人設定，選填身高與版型偏好；移除未參與建議的體重欄位。
- 設定天氣、手動氣溫、場合及心情，產生兩個版型與配色提案。
- 優先批量上傳衣服與飾品，不必預先分類。上傳後可逐件展開調整分類、主色、版型、厚薄與場合。
- 新上傳照片透過 Canvas 自動取主色：等比例縮至最長邊 64 像素、忽略透明度低於 50% 的像素，取最大 RGB 量化色群的加權平均。保留白色與黑色，主色可手動修正。未去背照片仍可能取到背景色；既有衣物不會自動覆寫。
- 衣物卡片提供「框選衣物取色」：拖曳選區或以滑桿調整，只分析選區並保存主色、候選色與百分比座標，原圖保留。人工選區內不再套用背景替換規則；沒有進行模型分割或去背。
- 雨天納入外套，寒冷時優先保暖衣物；指定輕薄單品時提醒添加保暖層。
- 結果依序顯示衣物組合、版型理由、配色與搜尋連結，第二套按需展開。
- 原始照片與衣物標籤保存於 IndexedDB，重新整理後可讀取；未分類衣物暫不參與搭配。
- 當天表單不永久保存。重置會先確認並保留衣櫥；另有清空本機衣櫥功能。
- 本機衣櫥依瀏覽器與網站來源區分（包括連接埠），不同裝置或網址不共用；清除網站資料、無痕模式或瀏覽器儲存空間回收可能使資料遺失，尚無雲端同步。
- 商品搜尋連結、精簡 Header 與側邊導覽。
- Open-Meteo 目前天氣查詢：選目前位置（按下按鈕後才請求定位）或搜尋目的地並從候選城市選擇。座標傳給 Open-Meteo，不永久保存；可手動覆寫。失敗時保留手動輸入。這不是出發日期的天氣預報。API 免費端點使用條件以官方規範為準，正式商用前需確認方案。
- 放大衣櫥視窗可勾選多件指定衣物，每個分類一件，兩套提案都保留。未分類衣物不可指定。
- 拍照加入使用行動瀏覽器的 `capture="environment"` 檔案輸入；是否開啟相機依裝置支援，桌面可能只顯示檔案選擇。沿用驗證、取色與保存流程。
- 版型偏好會影響選衣排序，結果列出符合的單品；缺少標籤時會說明未套用版型偏好。身高僅提供長度試穿提醒，不會推斷身形或尺寸。
- 手機與桌面響應式版面。

## 介面操作

參考 https://clothes-rec.vercel.app/ 的任務分組與輕量卡片層次，工作室聚焦於「活動與心情 → 天氣 → 衣櫥自動搭配／指定單品」。完整的分類、標籤編輯與取色管理仍在獨立衣櫥頁。頂部提供兩個主要頁面的快捷導覽，品牌按鈕保留側邊選單。沒有加入已移除的大型首頁介紹或尚未實作的 AI 功能。

- 工作室採活動／心情優先、次要天氣卡片與搭配方式分段控制；工作室只顯示精簡衣物預覽，詳細校正在獨立衣櫥頁操作。保留原有分類完整性防呆。視覺參考：https://clothes-rec.vercel.app/ ，未複製其服務或模型功能。

- 側邊選單分為 `#studio` 穿搭工作室、`#closet` 分類衣櫥、`#about` 關於我們、`#feedback` 回饋。切換頁面會保留搭配表單狀態。
- 移除 100 件的人為上限；仍受瀏覽器 IndexedDB 配額與裝置資源限制，單張上限維持 5 MB。儲存失敗時會提示，不會將未保存照片當成已加入。
- 標籤依資料維度區分顏色：分類綠、版型藍、厚薄橘、場合紫。衣物編輯以可動畫的展開／收合區顯示，支援減少動態效果偏好。
- 「重設搭配條件」會重設當天天氣、場合、心情、個人偏好、指定單品與結果，保留衣櫥。確認視窗會再次說明。
- 固定成功狀態文字已移除；失敗提示改為可關閉的通知。Footer 提供品牌、關於、回饋與本機保存說明。
- 回饋頁只準備內容，使用者需自行前往 GitHub 登入、確認送出，不會自動建立 issue。

- 「新增衣物」整合選擇照片與拍照兩種入口。
- 卡片以 hashtag 顯示已知的分類、版型、厚薄與場合；未設定資料不會假造標籤。
- 照片左下角主色圓點可開啟主色修改、候選色與框選取色工具。
- 放大衣櫥中點選未分類衣物會要求先分類，儲存成功後才勾選；取消不會改動資料。
- 天氣預設由地點查詢帶入，未查詢前不使用預設氣溫產生提案；手動設定僅作為收合的備用入口。
- 缺少項目以單行提示，無結果時不顯示佔位區；一般操作狀態放在 footer。

## 邊界

目前使用可解釋的規則搭配，模型服務尚未設定；沒有即時天氣或商品庫存串接。兩個方案在衣物不足時可能包含相同衣物。Google Fonts 需要連網，無法載入時使用系統字型。

## 後續模型擴充

白色色群採嚴格門檻：RGB 三通道皆 ≥245，且最大通道差 ≤6。其他亮色像素使用更細的色桶，避免白、米色、淺灰合併；不會刪除白色像素，也不會將符合條件的白色強制改成純白。此門檻為可調整的啟發式規則，仍無法區分白衣與白背景。

取色合併 RGB 距離不超過 24 的相近色桶（白色與非白色不合併），保存前兩色及全圖、邊緣與中央占比。當第一色也是邊緣占比最高的色群、占邊緣至少 50%，且邊緣占比比中央高至少 10 個百分點；第二色占全圖至少 3%、占中央至少 5%，中央占比比邊緣高至少 5 個百分點，則改選第二色。不再限制第一色占全圖的上下限。無足夠中央替代色證據時仍保留第一色。這是可調整的背景推測，不能取代去背。

主色、候選色票與背景提示直接顯示在衣物卡片外層；可點選切換。既有衣物不會自動重新分析。

`App` 接受選填的 `classifier` 函式，由 `prepareGarment(file, classifier)` 呼叫。介面為 `async (file: Blob) => ({category, fit, thickness, occasion, color, notes})`。透過 `src/classification.js` 驗證枚舉與色碼後預填，並保存 `prediction` 原始合法欄位和 `reviewed` 人工修改狀態。未設定時為 `not-configured`，錯誤或無效分類為 `failed`，有效預測為 `predicted`，都會保留原圖。人工修改不會再次呼叫模型覆蓋。備註可於編輯區輸入，失焦後保存。

分類：上衣／下身／外套／鞋子／配件；版型：自然／合身／寬鬆／直筒／高腰；厚薄：適中／輕薄／保暖；場合與介面選項一致。未設定欄位保留預設值。金鑰應放在後端，不要放入 Vite 前端環境變數。去背仍只預留處理狀態，尚無實作。`src/wardrobeStore.js` 專責本機資料保存。
